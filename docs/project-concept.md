# HazardNav project concept

## 日本語

### 概要

地震、火災、有毒ガスなどで人が建物に入れない場合、オペレーターは ROS2 のコマンドや座標プログラムを覚える必要がありません。「壁の 0.5 メートル手前まで進み、左に曲がり、右の壁に沿って落下物を通過し、緑の安全エリアで止まれ」と話すだけで、システムが検証可能な動作計画に変換します。ロボットは LiDAR、オドメトリ、カメラを使い、仮想環境内で動作を実行します。

### システム構成

1. **オペレーター端末**：テキスト入力またはキー操作による録音を受け取ります。音声は転写モデルでテキストに変換されます。
2. **言語任務プランナー**：大言語モデルは厳格な JSON 動作計画のみを出力し、Python コードを生成・実行しません。
3. **任務プロトコル**：指定距離の移動、回転、壁前までの移動、分岐までの移動、壁沿い走行、停止の 6 種類を扱います。速度、距離、角度、タイムアウトには制限があります。
4. **センサー実行器**：`/odom` で距離と角度、`/scan` で壁、分岐、危険な障害物を確認し、`/cmd_vel` で走行命令を送ります。
5. **自作救援ロボット**：Gazebo SDF で車体、2 つの駆動輪、補助輪、質量特性、摩擦、360° LiDAR、前方 RGB カメラを定義しています。
6. **危険な建物環境**：破損した通路、角、落下物、発光する火災エリア、青い出発エリア、緑の安全エリアを含みます。

### AI と制御の役割

言語モデルは多様な言い回しの理解に適していますが、モーターを高頻度で直接操作する用途には適していません。そのため、役割を次のように分けます。

```text
自然言語 / 音声
       ↓
大言語モデル：意図を理解し、制限付き動作計画を生成
       ↓
厳格な検証：未知の項目、制限外の数値、不完全な動作を拒否
       ↓
ROS2 実行器：LiDAR とオドメトリで各動作を確認
       ↓
Gazebo 内の自作差動二輪救援ロボット
```

この分離により、AI は言語理解に集中し、予測可能なプログラムが安全確認と走行制御を担当します。

### デモ手順

1. Gazebo の危険建物と救援ロボットを起動し、`/scan`、`/odom`、カメラ映像を表示します。
2. まず手作業の安全ルートを送り、AI なしでも車体制御が正しく動くことを示します。
3. オペレーターが新しい経路指示を入力または発話します。
4. AI が生成した構造化任務を表示します。
5. ロボットがステップごとに実行し、現在の動作、進捗、センサー状態を表示します。
6. 障害物が近すぎる場合の緊急停止を示し、経路を修正して安全エリアへ到達させます。
7. rosbag で実験を再生し、後から分析できることを示します。

### 定量評価

- **言語計画有効率**：自然言語命令が厳格な任務プロトコルを通過する割合。
- **任務成功率**：ロボットが安全エリアに入り、正常に停止する割合。
- **経路実行誤差**：指定距離と回転角度のオドメトリ誤差。
- **最小安全距離**：実行中に LiDAR が記録した最小障害物距離。
- **計画遅延**：利用者の入力から構造化計画の発行までの時間。
- **介入回数**：1 回の任務で、人が指示を言い直す、または取り消す必要があった回数。

### 今後の拡張

- カメラ映像に火炎、煙、非常口マークの認識を追加し、言語計画が視覚イベントを参照できるようにします。
- Nav2 を追加し、言語が目的地を指定し、Nav2 が全体経路を計画し、現在の実行器が近距離の安全を守る構成にします。
- 動く落下物や通信遅延を追加し、不安定なネットワークでの回復を評価します。
- 音声転写、動作計画、カメラ、LiDAR マップ、緊急停止を同時に表示する Web パネルを作成します。
- 仮想ロボットの差動二輪パラメータを小型実機に移植し、オドメトリと壁距離の差を比較します。

## English

### Concept

When an earthquake, fire, or toxic gas makes a building unsafe for people, the operator does not need to know ROS2 commands or coordinate programming. The operator can say, "Move to half a metre before the wall, turn left, follow the right wall past the debris, and stop in the green safe zone." The system converts this request into a verifiable action plan, and the robot executes it in simulation with LiDAR, odometry, and camera feedback.

### System components

1. **Operator station**: accepts typed commands or push-to-talk recordings. A transcription model converts speech into text.
2. **Language mission planner**: the language model produces only a strict JSON action plan. It never generates or executes Python source code.
3. **Mission protocol**: supports six actions—move a distance, turn, move until a wall, move until a junction, follow a wall, and stop. Speed, distance, angle, and timeout values all have limits.
4. **Sensor-driven executor**: uses `/odom` for distance and angle, `/scan` for walls, junctions, and emergency obstacles, and publishes motion through `/cmd_vel`.
5. **Custom rescue robot**: its Gazebo SDF defines the chassis, two driven wheels, caster, mass properties, friction, 360-degree LiDAR, and front RGB camera.
6. **Hazardous building**: includes damaged corridors, corners, debris, a glowing fire area, a blue start area, and a green safe zone.

### Roles of AI and control software

Language models are good at understanding many ways of expressing the same request, but they should not directly control motors at high frequency. The project separates these roles:

```text
Natural language / speech
       ↓
Language model: understand intent and create a constrained action plan
       ↓
Strict validator: reject unknown fields, out-of-range values, and incomplete actions
       ↓
ROS2 executor: confirm each action with LiDAR and odometry
       ↓
Custom differential-drive rescue robot in Gazebo
```

This separation lets AI focus on language understanding while predictable software handles safety checks and motion control.

### Demo flow

1. Start the Gazebo hazardous building and rescue robot, and show `/scan`, `/odom`, and the camera image.
2. Publish a hand-authored safe route first to show that the robot control works without AI.
3. The operator types or speaks a new route instruction.
4. Display the structured mission generated by AI.
5. The robot executes one step at a time while the interface shows the current action, progress, and sensor state.
6. Demonstrate an emergency stop when an obstacle is too close, then revise the route and reach the safe zone.
7. Replay the mission with rosbag to show that the run can be analysed later.

### Measurable evaluation

- **Valid language-plan rate**: percentage of natural-language commands that pass the strict mission protocol.
- **Mission success rate**: percentage of runs in which the robot enters the safe zone and stops normally.
- **Execution error**: odometry error for distance and turn actions.
- **Minimum safety clearance**: shortest obstacle distance recorded by LiDAR during a mission.
- **Planning latency**: time from operator submission to structured-plan publication.
- **Intervention count**: number of times the operator must restate or cancel a command.

### Future extensions

- Add fire, smoke, and exit-sign recognition so that language plans can refer to visual events.
- Add Nav2 so language specifies the destination, Nav2 plans the global path, and the current executor protects near-field safety.
- Add moving debris and communication delay to test recovery on unreliable networks.
- Build an operator web panel that combines speech transcription, action plans, camera video, a LiDAR map, and an emergency-stop button.
- Transfer the simulated differential-drive parameters to a small physical robot and compare odometry and wall-distance errors.

## 中文

### 概念

当地震、火灾或有毒气体使建筑内部不适合人员进入时，操作员不必掌握 ROS2 指令或坐标编程。操作员只需说“向前走到墙前半米，左转，沿右侧墙通过坠落物，在绿色安全区停止”，系统就会将请求转换为可验证的动作计划。机器人结合 LiDAR、里程计和相机反馈在仿真环境中执行这些动作。

### 系统组成

1. **操作员端**：接收文字命令或按键录音，语音通过转录模型变成文字。
2. **语言任务规划器**：语言模型只输出严格的 JSON 动作计划，不生成或执行 Python 代码。
3. **任务协议**：支持定距离移动、转向、走到墙前、走到岔路、沿墙行驶和停止六种动作。所有速度、距离、角度和超时都有限制。
4. **传感器执行器**：使用 `/odom` 判断距离和角度，使用 `/scan` 判断墙体、岔路和紧急障碍物，通过 `/cmd_vel` 发送运动命令。
5. **自建救援车**：Gazebo SDF 中定义了底盘、两个驱动轮、脚轮、质量特性、摩擦、360° LiDAR 和前视 RGB 相机。
6. **危险建筑场景**：包含受损走廊、墙角、坠落物、发光火灾区域、蓝色出发区和绿色安全区。

### AI 和控制程序的分工

语言模型适合理解同一意思的多种表达，但不应高频率地直接控制电机。项目将职责分为：

```text
自然语言 / 语音
       ↓
语言模型：理解意图并生成受限动作计划
       ↓
严格校验器：拒绝未知字段、越界数值和不完整动作
       ↓
ROS2 执行器：使用 LiDAR 和里程计确认每个动作
       ↓
Gazebo 中的自建差动轮救援车
```

这种分工让 AI 专注于语言理解，让可预测的程序负责安全检查和运动控制。

### 演示流程

1. 启动 Gazebo 危险建筑和救援车，展示 `/scan`、`/odom` 和相机画面。
2. 先发布手写安全路线，证明在没有 AI 时机器人控制也能正常工作。
3. 操作员输入或说出新的路线指令。
4. 展示 AI 生成的结构化任务。
5. 机器人逐步执行，界面持续显示当前动作、进度和传感器状态。
6. 障碍物过近时展示紧急停止，修改路线后重新到达安全区。
7. 使用 rosbag 回放任务，说明本次运行可以在事后分析。

### 可量化评价

- **语言计划有效率**：自然语言指令通过严格任务协议的比例。
- **任务成功率**：机器人进入安全区并正常停止的比例。
- **路线执行误差**：定距离动作和转向动作的里程计误差。
- **最小安全距离**：执行期间 LiDAR 记录的最近障碍物距离。
- **计划延迟**：从操作员提交命令到发布结构化计划的时间。
- **人工干预次数**：完成一次任务时，操作员需要重述或取消命令的次数。

### 后续扩展

- 在相机画面中加入火焰、烟雾和出口标志识别，让语言计划可以引用视觉事件。
- 接入 Nav2：语言只指定目的地，Nav2 负责全局路线，当前执行器负责近距离安全。
- 增加移动坠落物和通信延迟，测试不可靠网络下的任务恢复。
- 制作操作员 Web 面板，同时显示语音转录、动作计划、相机、LiDAR 小地图和紧急停止按钮。
- 将仿真中的差动轮参数迁移到小型实体车，比较里程计和墙距误差。
